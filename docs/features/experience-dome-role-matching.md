# Experience Dome — Role Matching Engine

## Concept

"What do I want to be when I grow up?" is the wrong question. The answer is always anchored to job titles, but it should be anchored to experiences. A "Stand-up comedian" is really: performing live + writing material + reading a room + being vulnerable on stage + creating content. Someone whose dome lights up on those 5 nodes but has never considered comedy would see it as an 85% match.

## Data Model

### Role Experiential Fingerprint
Each career role = a set of weighted dome node IDs, like a fingerprint.

```json
{
  "id": "retreat-facilitator",
  "title": "Retreat Facilitator",
  "onetCode": "39-9032.00",
  "category": "experiential",
  "primaryPrimals": ["bonds", "healing", "movement"],
  "nodes": {
    "sub-somatic-1400": 0.9,
    "sub-ritual-2018": 0.8,
    "sub-dance-1975": 0.7
  },
  "description": "Designing and holding space for group transformation through breathwork, movement, and ceremony"
}
```

### Matching Score
Dot product of user's dome ratings × role's experiential fingerprint.

User state weights: vibe_rise=1.0, fun=0.7, growth_edge=0.4, pressure=0.3, bored=-0.5, null=0

Match % = score / max_possible_score × 100

### Node Tiers (eliminates generic inflation)

| Tier | Definition | In matching? |
|------|-----------|-------------|
| Infrastructure | Most adults do this regardless of role (email, phone, computer, coffee, banking, smartphone) | Excluded |
| Professional | Common across a category (presenting, LinkedIn, WFH) | Low weight (0.2-0.3) |
| Distinctive | Specific to this role (breathwork for facilitators, cooking for chefs) | High weight (0.7-1.0) |

Infrastructure nodes should be identified programmatically: any node appearing in 70%+ of all role fingerprints, plus a manually curated list of "everyone does this" experiences.

## Data Pipeline — O*NET Bridging

### The Problem
O*NET has 41 broad work activities (e.g., "Performing for the Public"). Our dome has 330 specific experiential nodes. One O*NET activity maps to many dome nodes, and WHICH specific ones depends on the role's industry.

### The Solution: Two-Step Bridge

**Step 1: O*NET Activity → Dome Node Clusters**

Each O*NET activity maps to a cluster of related dome nodes:

```
"Performing for the Public" → [
  sub-oral-1400c (live performance),
  sub-oral-1860 (stand-up comedy),
  sub-oral-2006 (TED talk),
  sub-dance-1975 (ecstatic dance),
  sub-somatic-1400 (breathwork facilitation),
  sub-coaching-2010 (coaching session)
]
```

**Step 2: Role Industry Context → Node Selection**

For a specific role, the O*NET importance score for "Performing for the Public" determines the WEIGHT, and the role's industry determines WHICH nodes from the cluster:

- Fitness Trainer + "Performing for Public: 85" → `sub-strength-2000` (CrossFit) at 0.85
- Podcast Host + "Performing for Public: 92" → `sub-oral-2015` (live podcast) at 0.92
- Retreat Facilitator + "Performing for Public: 78" → `sub-somatic-1400` (breathwork) at 0.78

### O*NET Data Access

**API**: https://services.onetcenter.org/ws/ (requires free registration)
**Download**: https://www.onetcenter.org/database.html (CSV, quarterly updates)
**Key files**: `Work Activities.txt` (41 activities × 1016 occupations with importance scores)

### Implementation Steps

1. Register for O*NET Web Services API key
2. Download `Work Activities.txt` — get importance scores for all occupations
3. Build the bridging table: 41 O*NET activities → dome node clusters
4. For each of the 10 test roles, pull O*NET scores and auto-generate fingerprints
5. Cross-validate against the AI-generated fingerprints (v1, at `src/data/roleExperienceFingerprints.json`)
6. Iterate on the bridging table until outputs match human intuition

### Validation Sources

| Source | What it provides | How to use |
|--------|-----------------|-----------|
| O*NET Work Activities | Importance scores per role (0-100) | Primary: drives fingerprint weights |
| BLS Time Use Survey | Hours/day spent on activities by occupation | Secondary: sharpens weights |
| BLS Occupational Outlook Handbook | "What they do" prose per role | AI extraction: catch missing nodes |
| O*NET Detailed Work Activities | 2,000+ specific tasks per role | Granular validation of node selection |

## User Flow Vision

1. User completes dome onboarding (rates 58 core experiences)
2. Matching engine runs their dome against all role fingerprints
3. Results page shows: "Based on your experiences, your top matches are..."
4. Each match shows dome overlay (your shape vs the role's shape, green=overlap, amber=gap)
5. "Growth edge" gaps become suggested courage challenges
6. "How will you experience this?" → Career / Holiday / Hobby / Start yourself → Quest creation
